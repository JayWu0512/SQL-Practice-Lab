SQL Fundamentals

Retrieve, filter, summarize, and combine data.

Start with: What problem am I trying to solve?

Choose the information you need

Scenario: A regional marketing analyst is preparing a small address-targeting sample.

Task: Produce a 20-row customer-location list. Each row must contain exactly customer_id, customer_city, and customer_state.
What is missing without SELECT?
SELECT * returns every column. It is useful for quick exploration, but a final report should show only the fields the analyst needs.

    customer_city,
    customer_state
FROM customers
LIMIT 20;

FROM customers
LIMIT 10;

Choose the rows you need

Scenario: The São Paulo regional manager wants to review customers served by that state only.

Task: Show up to 20 customers whose state is São Paulo (SP). No other states should appear.
Without WHERE: the report includes customers from every state, so it cannot answer the manager’s regional question.

    customer_state
FROM customers

DISTINCT + ORDER BY + LIMIT

Explore, rank, and focus

Task A: Return one alphabetized list of every state code represented by a customer—no duplicates.

Task B: Return exactly 10 products with a known weight, from heaviest to lightest.
DISTINCT
One copy of each state.
ORDER BY + LIMIT
Rank values, then keep the top N.
SELECT DISTINCT customer_state
FROM customers
ORDER BY customer_state;

    product_category_name,
    product_weight_g
FROM products
WHERE product_weight_g IS NOT NULL
ORDER BY product_weight_g DESC
LIMIT 10;

GROUP BY

One summary for each category

Scenario: An expansion team must decide where the customer base is strongest before choosing a city for the next warehouse.

Task: Produce one row for every customer_state with that state’s customer count. Put the largest count first.
COUNT(*)
One total for the whole table.
GROUP BY + COUNT(*)
One total for SP, RJ, MG, and every other state.
SELECT
    customer_state,
    COUNT(*) AS customer_count
FROM customers
    GROUP BY customer_state
ORDER BY customer_count DESC;
Expected columns: customer_state | customer_count
Each state becomes one output row.
GROUP BY splits the input into state groups; COUNT then calculates one number inside each group.
Input stateGrouped outputSP, SP, SPSP → 3RJ, RJRJ → 2MGMG → 1

JOIN

Reconnect related tables

Scenario: A customer-support lead needs the customer’s location beside each order’s current status.

Task: Build a 20-row report showing customer ID, city, state, order ID, and order status.
flowchart LR
      customer_table["customers"] --> order_table["orders"]

Match the tables with customers.customer_id → orders.customer_id.

Without JOIN: customer location and order status live in separate tables. Manual ID matching would be repetitive and error-prone.
SELECT
    c.customer_id,
    c.customer_city,
    c.customer_state,
    o.order_id,
    o.order_status
FROM customers AS c
JOIN orders AS o
    ON c.customer_id = o.customer_id
LIMIT 20;
What SQL does: c and o are aliases. The ON clause tells SQL which customer_id values describe the same customer-order relationship.
customers AS ccustomer_id = A1
city = São Paulo
A1 = A1
orders AS ocustomer_id = A1
order_status = delivered

Scenario: A pricing analyst is investigating unusually expensive purchases and defines “expensive” as above the company’s average order-item price.

Task: Return up to 20 above-average order items, sorted by price descending.

    order_id,
    price
FROM order_items
WHERE price > (

LIMIT 20;

WHERE customer_id IN (

COMBINING SKILLS

State revenue

Scenario: The sales director is allocating regional advertising budget.

Task: Return one row per customer state with total_revenue, defined as the sum of order_items.price for purchases by customers in that state. Sort highest to lowest. Do not include freight.

customer_state customers   price order_items   link orders

total SUM   per state GROUP BY   largest first ORDER BY DESC

SELECT
    c.customer_state,
    ROUND(SUM(oi.price)::numeric, 2) AS total_revenue
FROM customers AS c
JOIN orders AS o
    ON c.customer_id = o.customer_id
JOIN order_items AS oi
    ON o.order_id = oi.order_id
GROUP BY c.customer_state
ORDER BY total_revenue DESC;
Expected columns: customer_state | total_revenue. One row represents every qualifying purchase for one state.
This combines a JOIN with a grouped aggregate: connect each item price to its customer state, add prices within each state, then rank states by the total.
Joined rowsSP → 20
SP → 30
RJ → 40
→
SUM by stateSP → 50
RJ → 40
→
ORDER BY DESCSP first
RJ second

CTE

Same problem, two valid solutions

Scenario: Finance wants states performing better than a typical state—not states with a high individual-item price.

Task: Calculate each state’s total item-price revenue, then return only totals above the average state total.
flowchart LR
      state_revenue["State revenue totals"] --> average_state["Average state total"]
      state_revenue --> above_average_states["States above average"]
      average_state --> above_average_states

First: preserve the original non-CTE solution. Then: show the original CTE version.

CTE comparison: without a CTE

This original solution works, but state-revenue logic is nested and repeated.
SELECT *
FROM (
    SELECT
        c.customer_state,
        SUM(oi.price) AS total_revenue
    FROM customers AS c
    JOIN orders AS o ON c.customer_id = o.customer_id
    JOIN order_items AS oi ON o.order_id = oi.order_id
    GROUP BY c.customer_state
) AS state_revenue
WHERE total_revenue > (
    SELECT AVG(total_revenue)
    FROM (
        SELECT SUM(oi.price) AS total_revenue
        FROM customers AS c
        JOIN orders AS o ON c.customer_id = o.customer_id
        JOIN order_items AS oi ON o.order_id = oi.order_id
        GROUP BY c.customer_state
    ) AS all_state_revenue
)
ORDER BY total_revenue DESC;

CTE comparison: with a CTE

The original CTE version gives the first logical step a name: state_revenue.
WITH state_revenue AS (
    SELECT
        c.customer_state,
        SUM(oi.price) AS total_revenue
    FROM customers AS c
    JOIN orders AS o ON c.customer_id = o.customer_id
    JOIN order_items AS oi ON o.order_id = oi.order_id
    GROUP BY c.customer_state
)
SELECT
    customer_state,
    ROUND(total_revenue::numeric, 2) AS total_revenue
FROM state_revenue
WHERE total_revenue > (
    SELECT AVG(total_revenue)
    FROM state_revenue
)
ORDER BY total_revenue DESC;
Step 1: create state_revenue. Step 2: analyze that named result. The CTE improves structure; it does not make the non-CTE answer invalid.
WITH state_revenueSP → 12,000
RJ → 8,000
→

CASE WHEN

Turn values into business categories

Scenario: A merchandising manager wants a simple price-band report for non-technical stakeholders.

Task: Show 20 order items with price_category: Low below 50, Medium from 50 to under 200, and High at 200 or more.
SELECT
    product_id,
    price,
    CASE
        WHEN price < 50 THEN 'Low'
        WHEN price < 200 THEN 'Medium'
        ELSE 'High'
    END AS price_category
FROM order_items
LIMIT 20;
CASE WHEN translates raw values into labels. It is useful for segmentation, reporting labels, and business rules.
price < 50Low
50–199.99Medium
price ≥ 200High

WINDOW FUNCTIONS

Rank without collapsing rows

Scenario: A category manager wants the most expensive purchased items within each product category while still seeing every item.

Task: Rank each order item by price within its category.
GROUP BY
Reduces rows into a summary.
Window function
Keeps rows and adds a calculation across them.
SELECT
    p.product_category_name,
    oi.product_id,
    oi.price,
    RANK() OVER (
        PARTITION BY p.product_category_name
        ORDER BY oi.price DESC
    ) AS price_rank
FROM order_items AS oi
JOIN products AS p
    ON oi.product_id = p.product_id
WHERE p.product_category_name IS NOT NULL
ORDER BY p.product_category_name, price_rank
LIMIT 30;
PARTITION BY restarts ranking per category. ORDER BY inside OVER determines who is rank 1.
categoryprice → rankbooks80 → 1books45 → 2toys60 → 1toys20 → 2

Optional

Recursive CTE

The original tutorial uses a small standalone example because Olist has no natural hierarchy.

WITH RECURSIVE countdown AS (
    SELECT 3 AS number
    UNION ALL
    SELECT number - 1
    FROM countdown
    WHERE number > 1
)
SELECT number
FROM countdown;
A recursive CTE has a starting row, then repeatedly uses its previous output to create the next row. The condition stops the loop.
Startnumber = 3
→
Repeat3 − 1 = 2
2 − 1 = 1
→
Stopnumber is no longer
greater than 1

Mini-Test 3 — Uber interview (Medium)

Question: Treat each row in orders as one transaction. For every customer_unique_id, return that customer’s third chronological order.

Output: customer_unique_id, order_id, and order_purchase_timestamp. Exclude customers with fewer than three orders. If timestamps tie, order by order_id.

Interview source: Adapted for the Olist dataset from DataLemur’s User’s Third Transaction — Uber, Medium.

Try your SQL

This follows the source question’s small, direct output: one third transaction per qualifying customer.

Use ROW_NUMBER() partitioned by customer_unique_id, ordered by order timestamp and order ID. Then keep row number 3.
customer A orderROW_NUMBER()2022-01-0812022-01-1022022-02-053 — keep
WITH ranked_orders AS (
    SELECT
        c.customer_unique_id,
        o.order_id,
        o.order_purchase_timestamp,
        ROW_NUMBER() OVER (
            PARTITION BY c.customer_unique_id
            ORDER BY o.order_purchase_timestamp, o.order_id
        ) AS order_number
    FROM customers AS c
    JOIN orders AS o
        ON c.customer_id = o.customer_id
)
SELECT
    customer_unique_id,
    order_id,
    order_purchase_timestamp
FROM ranked_orders
WHERE order_number = 3
ORDER BY order_purchase_timestamp, order_id;

Mini-Test 4 — Apple interview (Simplified)

Question: For orders placed in 2018, calculate the total number of orders for each month.

Output: order_month and order_count. Sort from the earliest month to the latest.

Interview source: Simplified Olist monthly-performance adaptation inspired by DataLemur’s Apple SQL interview questions. This version uses the available orders table.

Try your SQL

Focus on one simple summary per month: filter, group, count, and sort.

Use DATE_TRUNC('month', order_purchase_timestamp) to create the month, then use COUNT(*).
orders2018-03-04
2018-03-19
2018-04-02
→
DATE_TRUNC2018-03
2018-03
2018-04
→
COUNT2018-03 → 2
2018-04 → 1
SELECT
    DATE_TRUNC('month', order_purchase_timestamp)::date AS order_month,
    COUNT(*) AS order_count
FROM orders
WHERE order_purchase_timestamp >= DATE '2018-01-01'
  AND order_purchase_timestamp < DATE '2019-01-01'
GROUP BY order_month
ORDER BY order_month;

Table management and CRUD reference

Use this in your own Supabase SQL Editor: these commands change data or database structure, so this teaching website deliberately does not run them. Copy the examples only after you understand each command, and use the separate sql_practice table—not the Olist tables.

1. Create a safe practice table

CREATE TABLE IF NOT EXISTS sql_practice (
    id BIGSERIAL PRIMARY KEY,
    student_name TEXT,
    score INT
);

2. Insert practice rows

INSERT INTO sql_practice (student_name, score)
VALUES
    ('Jay', 90),
    ('Alex', 85),
    ('Sam', 78);

3. Read the practice table

SELECT *
FROM sql_practice;

4. Update one row

UPDATE sql_practice
SET score = 95
WHERE student_name = 'Jay';

5. Delete one row

DELETE FROM sql_practice
WHERE student_name = 'Sam';

Important: always check the table name and WHERE clause before running UPDATE or DELETE. DROP TABLE permanently removes the table and its data.

SQL is not identical in every database

PostgreSQL shorthand used here

ROUND(AVG(price)::numeric, 2)

::numeric is PostgreSQL’s compact type-cast syntax.
More portable SQL spelling

ROUND(CAST(AVG(price) AS NUMERIC), 2)

Both expressions turn the average into a numeric value before rounding.

When moving between PostgreSQL, MySQL, SQLite, BigQuery, or SQL Server, check date functions, text matching, type casts, and limit syntax. The PostgreSQL type-cast documentation explains both cast forms.

Example: top five customer states

Business question: Which five states have the most customers? Solve it once with SQL, then recreate the same result in pandas.

SQL

SELECT
    customer_state,
    COUNT(*) AS customer_count
FROM customers
GROUP BY customer_state
ORDER BY customer_count DESC
LIMIT 5;

pandas

top_states = (
    customers
    .groupby("customer_state")
    .size()
    .reset_index(name="customer_count")
    .sort_values("customer_count", ascending=False)
    .head(5)
)

The same idea appears in both languages: group by state, count rows, sort descending, and keep five rows.
